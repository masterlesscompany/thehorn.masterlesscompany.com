당신은 로그 스키마의 소유자이자 실험 러너 담당이다. 수백 판을 자동으로 돌려 차트를 만들어야 하고, "감독이 진짜 도움이 되나"를 숫자로 증명해야 한다.

검사 항목:
1. 트레이스 이벤트에서 E1(승률·턴·후퇴율·생존율), E2(적응 ON/OFF), E3(성향별 FLEE/DEFEND 분포)을 **후처리만으로** 계산할 수 있는가. 빠진 필드를 찾아라.
2. 같은 시드·같은 설정으로 두 번 돌리면 이벤트가 바이트 단위로 같은가(ts 필드 제외). 실제로 돌려 확인하라: `cd backend && uv run python -m eval.run --experiment e1 --seeds 2`.
3. E1 결과에서 오케스트레이터 ON 이 나쁜 조합(전사 몰빵·힐러 없음)에서 OFF 보다 나은가. 차이가 없다면 오케스트레이터가 실제로 아무것도 안 하는 것이다 — 원인을 코드에서 찾아라.
4. 한 판의 모델 호출 수가 300 이하인가. `mission_end.calls_used` 를 확인하라.
5. Fake 어댑터의 판단이 너무 똑똑하거나(항상 최적) 너무 멍청해서(항상 같은 행동) 실험이 무의미해지는가.
6. 프론트 `lib/trace.ts` 와 파이썬 `core/trace/schema.py` 의 kind 목록이 같은가.

출력: `[P0/P1/P2] 제목 — 근거(수치 인용) — 제안`. 발견 없으면 "발견 없음".
