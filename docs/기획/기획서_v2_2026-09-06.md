## 0. 한 줄 정의

**"제약 조건 하에서 자율 판단·협업·장기계획을 수행하는 멀티에이전트 시스템 — 게임을 검증 환경(testbed)으로 사용한다."**

- 유저는 캐릭터를 조종하지 않는다. 방향을 정하고, 조합을 고르고, 결과를 관찰한다.
- 캐릭터는 성격·신체·생애에 따라 따르거나 거부한다. 행동의 누적이 성격을 바꾸고, 전장에서 협상하고 도망가고 희생한다.
- 오케스트레이터는 유저가 준 로스터(좋든 나쁘든)로 최선을 찾고, 싸울 가치가 없으면 포기한다.
- **이 전부가 로그로 추적되고, 실험으로 측정된다.**

앞 절반은 게임 트레일러, 뒤 절반은 기술 문서 — 이 이중성이 프로젝트의 정체성.

## 2. 스코프 — 세 단계

모든 기능은 아래 세 칸 중 하나에 속한다. 12장 절단선 표가 기능별 매핑이다.

| 단계 | 시점 | 정의 | 판단 기준 |
|---|---|---|---|
| **A. 제출본** | 9/20 | 배포되어 돌아가고, 투표 사용자가 한 판 플레이할 수 있는 상태 | 완결성. 규모 아님 |
| **B. 데모데이본** | 10/17 | 심사위원 앞 10분 시연 + 실험 차트 | 4.8 데모 시나리오가 인스펙터로 설명 가능한가 |
| **C. 비전** | 이후 | 20판 캠페인·랭크·생애 전체 | 기획서 완결성. 발표에서는 로드맵 슬라이드 |

**절단 기준 하나**: 대표 데모 시나리오 한 판(4.8)에 필요하지 않은 시스템은 슬라이드로 보낸다.

**A→B의 핵심 차이**: 1판 → 2판 + 인터미션. 인터미션이 있어야 육성·거부·생애 이벤트가 존재하고, 이벤트 이후 전투가 있어야 "이벤트→판단 변화" 인과가 닫힌다.

## 3. 팀 구성 — 코어 2 + 위성 3

### 3.1 원칙
- 5명의 여유는 **코어 게임 시스템 확장에 쓰지 않는다.** 코어 상태 머신을 건드리는 기능(캠페인·랭크·PvP·관계축·반사실)은 통합 표면을 곱셈으로 늘린다.
- 여유는 **코어를 건드리지 않고 코어의 출력(로그)을 소비하는 일**에 쓴다: 평가, UI, 콘텐츠, 배포.
- 근거: 정리본 5.3 "검증 표면적을 팀의 검증 능력 이내로". 참조 사례(라이프 튜토리얼 팀)에서 실질 개발 2석 + AI 위임으로 하루 수십 버전이 나왔고, 병목은 타이핑이 아니라 검증·통합·프론트 폴리싱이었다.

### 3.2 역할
| 역할 | 담당 범위 | 첫 주 산출물 |
|---|---|---|
| **코어 A** | 규칙 엔진(순수 도메인, 유닛테스트), 하네스(JSON 스키마·검증·재시도·LLM 포트), **Fake/Replay 어댑터**, 진영 대칭 전투 엔진 | 엔진 + 로그 스키마 구현 |
| **코어 B** | 오케스트레이터·캐릭터 에이전트 프롬프트, 재계획 트리거, 승산 휴리스틱, 보스 in-context 적응 | 한 판 완주 |
| **평가·실험** | **로그 스키마 소유자**, 실험 러너, 자동 대전(PvP 엔진 재사용), 분포 차트, 모델 벤치마크, 결산 리포트 계산층 | 실험 러너 + Fake 로그로 차트 1개 |
| **프론트·배포** | 3패널 트레이스 뷰어(Fake 데이터로 첫날부터), **9/12 전 실도메인 배포**, 투표 사용자 진입 화면 | 배포된 껍데기 + 서사 스트림 패널 |
| **콘텐츠·발표·PM** | 세계관, 캐릭터 프로필 5종, 이벤트 스키마 초안, 시드 시나리오, 발표자료, 리허설 진행, 투표 대응 | 프로필 5종 + 이벤트 카테고리 초안 |

### 3.3 첫 이틀의 계약 — 판정 로그 스키마
5명이 흩어지기 전에 **트레이스 이벤트 포맷**을 JSON 스키마로 고정한다. 오케스트레이터 판단, 캐릭터 행동, 승산 휴리스틱, 재계획 트리거, 파라미터 diff, 순응 판정, 이벤트 효과 — 이 포맷을 기준으로 코어는 쓰고, 평가·프론트는 Fake 데이터로 동시에 읽는다. (참조 사례의 "API 계약 우선 + MSW 목" 방식)

### 3.4 검증 날
- 9/20 앞 **1일**, 10/17 앞 **2일**은 새 기능 없이 "만든 것이 도는지만 확인하는 날"로 캘린더에 고정. 5명이 각자 다른 경로로 완주한다.
- 통합 디버깅 30% 예약(정리본 9.3 유지).

## 4. 캐릭터 시스템

### 4.1 생성 — 탄생과 방향

로스터는 **지급**되고, 각 캐릭터의 **초기 방향성은 유저가 결정**한다.

```
[1] 지급     : 로스터 N명 (비전 10 / A·B 단계 5). 각자 신체 주사위 1회 굴려진 상태로 지급
[2] 관찰     : 유저가 키·체형·몸무게·(MBTI 표기)를 본다
[3] 방향 결정: 유저가 각 캐릭터에 ① 능력치 초기 포인트 분배 ② 클래스 ③ 성별 을 정한다
[4] 이후     : 유저 손을 떠난다. 세부 육성·빌드는 AI, 순응 여부는 캐릭터
```

- **주사위는 탄생 1회 한정.** 신체(키·체형·몸무게)는 이후 변하지 않는다. 유일한 예외는 3.8의 부상(장애).
- 순서가 중요하다: 몸을 먼저 보고 클래스와 능력치를 맞춘다. 스카우트가 선수 몸을 보고 포지션을 정하는 구조.
- **"육각형이 좋은 게 아니다."** 도적은 마르고 가벼운 신체가 맞다. 모든 신체가 높을 필요가 없고, 신체–클래스–능력치의 **정합**이 강함을 만든다. 마른 캐릭터를 전사로 키우는 것도 유저 자유(트롤픽 허용, 4.4 효율 페널티로 귀결).

### 4.2 능력치 6종 — "모든 속성은 판단 분기를 만들어야 한다" (정리본 3.1 원칙)

| 능력치 | 뜻 | 무엇을 바꾸는가 | 관할 |
|---|---|---|---|
| 힘 | 근력 | 물리 피해, 중량 장비 효율 | 규칙 엔진 |
| 민첩 | 몸놀림 | 명중·회피, 행동 순서 | 규칙 엔진 |
| 체력 | 버티는 힘 | HP, 스태미나, 피로 회복 속도 | 규칙 엔진 |
| 지능 (지성) | 똑똑함 | 마법 위력, 숙련 성장률(육성 효율) | 규칙 엔진 |
| **지혜 (이성)** | 판단력 | **캐릭터 에이전트에 주입되는 정보의 해상도** — 낮으면 아군 상태·적 패턴·방침 의도 일부가 프롬프트에서 가려짐, 높으면 전부 보고 판단. 수읽기 깊이 | 프롬프트 조립 |
| 행운 | 운 | 실행 판정·치명타 **굴림에만** 소폭 보정. 판단 로직에는 개입하지 않음 | 규칙 엔진 |

- 지성과 이성의 분리: **지능은 수치를 올리고, 지혜는 볼 수 있는 것을 늘린다.** 구현은 프롬프트 조립 시 필드 마스킹이라 비용이 거의 없다.
- 행운을 판단에 걸지 않는 이유: "그냥 랜덤 아니에요?"의 근거가 되고, 성향별 행동 분포 실험(10장)을 오염시킨다. 폭은 작게.

### 4.3 신체 (주사위) vs 능력치 (포인트) — 경계

| | 신체 | 능력치 |
|---|---|---|
| 결정 | 탄생 시 주사위 1회 | 유저 포인트 (초기 + 매 회차) |
| 변화 | **불변** (예외: 부상) | 성장 |
| 역할 | **효율 스펙트럼** — 이 장비가 이 몸에 맞는가 ("장착 가능하나 명중 -30%, 스태미나 2배") | **수치** — 피해·HP·명중치 |
| 항목 | 키, 체형(마른/보통/건장), 몸무게 | 힘·민첩·체력·지능·지혜·행운 |

기준: **훈련으로 변하는 것은 능력치, 타고나서 안 변하는 것은 신체.**

### 4.4 성별

- 유저가 선택한다. 키·몸무게를 보고 유저가 판단해도 된다.
- **전투·능력치·판단 엔진에 영향 0.** 표현 레이어(이름·대사 톤·서사)와 **생애 이벤트의 사유**에만 관여한다.
- 생애 이벤트에서 성별별 이탈 사유가 다를 수 있다(6.2). 단 **기대 이탈 비용(평균 이탈 턴 수)은 성별 간 동일하게 시뮬레이션으로 튠**한다(10장 실험). 성별 차이는 어떤 사유로 빠지느냐라는 서사의 차이일 뿐, 기대 비용의 차이가 아니다.
- 정리본 3.1의 "성별 제외" 결정을 위 조건부로 철회한다.

### 4.5 성향 4축과 MBTI (정리본 3.1·3.2 유지)
- 판단 축 4개: 위험 성향 / 협동 성향 / 계획 성향 / 희생 수용도 — LLM 프롬프트 관할
- 내부는 수치, 외부 표현은 MBTI 스타일. 가중치 테이블 방식(방식 B). LLM이 MBTI를 직접 해석하는 방식 A는 금지.
- **성향은 지급 시 시드로 결정, 유저 불가 (제안 — 14장 TODO).** 성격은 태어나는 것이고, 유저가 정하면 실험 변수가 오염된다. 유저는 MBTI 표기로만 본다.
- 상황 맥락(환경·HP·아군 상태)은 캐릭터 정의와 분리해 매 턴 주입.

## 5. 성장 시스템 — 세 층

"세부 육성은 AI"와 "유저가 포인트를 찍는다"가 모순되지 않게 층을 나눈다.

| 층 | 대상 | 결정자 | 메커니즘 |
|---|---|---|---|
| **방향** | 능력치 6종 | **유저** | 매 회차 종료 시 성장 포인트 지급(예: 10·5, 미션 난이도별 — 수치 TODO) → 포인트 찍기. **은행 가능**(모아두기), "추천 배분 수락" 버튼(단순 UI 편의, 조언 시스템 3.10과 무관) |
| **세부** | 숙련·빌드 (무기 숙련, 스킬, 전투 스타일) | **AI** | 육성 턴에서 캐릭터 신체·능력치·클래스를 보고 판단. "키 작고 힘 센 전사 → 긴 창 비효율, 워해머" |
| **통제 밖** | 컨디션·성격·관계 | **캐릭터** | 순응/거부, 생애 이벤트, 트라우마·각성 |

- 정리본 3.5의 역성장(피로 누적)은 **숙련·컨디션에만** 걸린다. 유저가 찍은 포인트를 시스템이 뺏지 않는다.
- "한 명만 몰빵" 사회실험의 레버는 정확히 이 유저 포인트 배분이다.

### 5.1 육성 턴 (정리본 3.5 유지)
- 유저: 카테고리 지시(교육/훈련/휴식/여가)
- 순응 판정(성격 가중치 기반 결정론적 확률) → 순응 / 부분 순응 / 거부(다른 행동)
- 실행 판정(주사위 + 컨디션 보정, 성실→advantage, 피로→disadvantage)
- 거부 시 LLM이 대체 행동 서사 생성("훈련장 대신 술집") + 결과도 파라미터로 귀결
- 유저에겐 결과만 통보, 시스템은 전부 기록 — 관찰가능성 문제의 축소판
- 연구 질문: "항상 순응하는 캐릭터가 최강인가?"

## 6. 로스터 생애 주기

캐릭터 하나의 슬롯이 겪는 상태를 한 모델로 묶는다.

```
탄생(주사위 1회) → 방향 결정(유저) → 재적
  → [이탈: 복귀 예정] → 충원(주사위) → (대체자 사망 → 신입) → 복귀(점유자 탈퇴) → 재적
  → [이탈: 영구]       → 충원(주사위) → 재적
  → [사망]             → 충원(주사위) → 재적   ※ 사망 = 소멸
```

### 6.1 슬롯 상태 모델
- 슬롯 필드: `점유자`, `휴직 중 원소유자`(복귀 예정 이탈 시), `점유자 유형`(원소유자 / 경력 대체자 / 신입)
- 로스터 상한은 항상 N. 대체자가 자리를 점유하므로 초과가 생기지 않는다.

### 6.2 이탈 — 이벤트가 아니라 판단
- 이탈 사유는 생애 이벤트 카테고리로 생성된다. 예: 임신·출산, 부상 은퇴, 가족 간병, 가업, 징집, 회의(懷疑)로 인한 은퇴 등. **성별별 사유 목록은 다를 수 있다.**
- 이탈 여부와 **복귀 시점은 캐릭터가 판단**한다. 고정 규칙("N턴 후 복귀")이 아니다. 희생 수용도 높고 팀 우선이면 다음 미션까지 뛰고 이탈하거나 짧게 쉬고 복귀, 자기보존형이면 즉시 이탈하고 길게, 파티 사기가 바닥이면 복귀를 앞당기는 식. → 판정 인스펙터에 "왜 이 시점에 복귀했나"가 열린다. 페널티가 아니라 **에이전트 판단 사례**.
- **기대 이탈 비용 성별 대칭**: 밸런스 시뮬레이션으로 성별별 평균 이탈 턴 수를 동일하게 튠(10장 실험 추가).
- 이탈 ≠ 사망: 경험·관계는 보존된다(감쇄는 있음, 6.5).

### 6.3 충원 — 주사위
- 사망·영구 이탈·**복귀 예정 이탈** 모두 즉시 주사위 충원.
- **주사위 높음** → 이탈자와 유사한 능력치·클래스의 **경력자**. 신체·능력치·클래스 고정으로 들어옴, 유저는 받기만 함.
- **주사위 낮음** → **신입**. 초기 생성 절차(4.1) 재사용: 신체 주사위 → 유저가 능력치·클래스·성별 결정.
- **리롤 없음.** 있으면 운의 의미가 사라진다.
- **경력자도 팀 자산은 0.** 능력치는 비슷해도 이 파티와의 관계·신뢰·협동 패턴·상대 정보는 없다. 3.9의 명제("진짜 자원은 머릿수가 아니라 누적") 유지. 경력자도 온보딩이 필요하다.
- 주사위에 사기·승률 보정을 넣지 않는다(순수 굴림). 보정을 넣으면 죽음의 나선(3.8)이 가속된다. 순수 굴림은 바닥에서도 경력자가 올 수 있는 **회복 경로**로 작동한다.

### 6.4 대체자 (복귀 예정 이탈의 충원)
- 로스터 화면에 **대체자 표시** + "복귀 예정" 상태 표시(정확한 시점은 캐릭터 판단이라 불확정).
- **대체자에게 찍은 성장 포인트는 탈퇴 시 함께 사라진다.** 페널티가 아니라 실험 레버("언젠가 나갈 사람에게 투자하는가"). 유저가 알고 판단해야 하므로 표시가 필수.
- **대체자 사망 시 → 신입 고정 충원(주사위 없음).** 급하게 비는 자리에는 경력자가 오지 않는다. 같은 슬롯의 재충원은 신입 고정. 원소유자 복귀 시 그 신입과 교체.
- **대체자·신입의 사망도 3.8 사망 파급을 동일하게 받는다** — 사기 하락, 목격 트라우마, 생존율·피폐도 카운트. 빠지면 "대체자는 소모품" 전략이 최적이 된다. 그것도 사회실험이지만 시스템이 벌점을 안 주면 실험이 아니라 허점.
- 양면성은 그대로 둔다: 대체자가 죽고 신입이 들어와 전화위복이 될 수도, 한 자리에서 신입이 연쇄로 죽을 수도. **슬롯당 사망 횟수 분포**를 밸런스 시뮬레이션에서 확인해 발생하되 지배적 경로는 아니게 튠(10장).

### 6.5 복귀
- 원소유자가 복귀 → 현재 점유자(경력 대체자 또는 신입) 탈퇴.
- 능력치 유지. 관계·신뢰는 공백 기간에 비례해 감쇄. 첫 1~2 미션은 신인 보정보다 약한 **재적응 보정**.
- **성격 변화 트리거를 복귀 시점에 건다.** 출산 후 위험성향·희생수용도 이동 등 — 3.3 MBTI 변화 카드("카일이 변했다")가 가장 개연성 있게 발생하는 지점.
- 대체자 퇴장 서사는 LLM 한 줄 + 결산 리포트에 활약 기록 보존.

### 6.6 사망 (정리본 3.8 유지)
- 완전 소멸, 부활 없음. 장애(물리 제약 영구 변경), 트라우마(판단 축 영구 보정), 사기 하락, 관계 파급.
- 죽음의 나선 경고와 회복 경로(각성 분기, 휴식 가치, 장애 재적응, 멘토링) 유지.

### 6.7 이벤트 스키마 — effect 타입 (확정)
```
파라미터 변경 | 결장(N턴) | 이탈(복귀 예정 / 영구) | 충원(주사위 / 신입 고정) | 복귀(점유자 탈퇴) | 사망
```
카테고리 스키마 고정 + effect 범위 제한 — 자유도는 서사에, 안정성은 스키마에(정리본 3.4 유지).

## 7. 미션·캠페인 구조

### 7.1 에피소드 길이는 파라미터
| 단계 | N | 구조 |
|---|---|---|
| A 제출본 | **1판** | 보스전 1판. 인터미션 코드는 비어 있어도 됨 |
| B 데모데이본 | **2판** | 1판(일반 전투, 적응 OFF, 끝까지 싸워 이기는 판) → 인터미션(육성 1턴·거부 장면·생애 이벤트 1회·파라미터 diff) → 2판(보스전, 적응 ON, 이탈→재계획→승산 붕괴→포기) |
| C 비전 | **20판** | 랜덤 강제 PvP 3회 / 5회차마다 육성 5턴 / 20회차 보스전 / 장기전 50판 |

- 2판이 최소인 이유: 인터미션이 존재해야 육성·이벤트가 있고, 이벤트 이후 전투가 있어야 인과가 닫힌다. 1판·2판이 정리본 4.3의 "끝까지 싸우는 판 vs 포기하는 판" 대비이고, 적응 OFF/ON이 실험 1번을 플레이 안에서 보여준다.
- 3판을 안 하는 이유: 두 번째 인터미션이 보여줄 성격 변화 시스템은 C단계. 전투 1판 = 100~300 호출.
- 러너는 처음부터 "미션 N개 + 인터미션" 구조로 짜고 N만 바꾼다.

### 7.2 출전 인원 — 미션별 가변 (확정)
- 미션마다 출전 가능 인원이 다르다(예: 1, 3, 4, 5, 전원). **유저가 조합을 선택**한다.
- A·B 단계: 로스터 5, 출전 1~3. C 단계: 로스터 10, 출전 1~10.
- **전원 출전 미션은 활성 에이전트 수 = 호출 배수.** C단계에서도 빈도 제한. 비용 통제 원칙(출전·육성 중인 캐릭터만 에이전트화, 벤치는 데이터) 유지.
- "한 명만 계속 키우면 나머지는 실력이 부족해 나중에 죽는다" — 인원 제한 가변 + 참여 편중도·과로도 지표(3.14)가 이 사회실험을 채점한다.

### 7.3 PvP — 위치 이동
- **플레이어 미션으로는 C단계.** 3.12의 정당화(랜덤 강제·조언 없음·train/test 분리·육성 A/B)는 전부 캠페인 구조에 의존하므로 2판 에피소드에서는 존재 이유가 없다.
- **평가 도구로는 A단계부터.** 파티 vs 파티 자동 대전은 사람이 안 껴도 돌아가는 유일한 전투 → 성향 분포 실험, 밸런스 튠, 조합별 오케스트레이터 실험의 데이터 생성기.
- 전제: 코어 A가 규칙 엔진을 **진영(faction) 대칭**으로 짠다. 보스 = "유닛 1개 + 고정 정책 진영". 보스전과 PvP가 같은 코드 경로.

### 7.4 로스터 규모
- A·B: **5명 / 출전 3**. 편성 판단(선택하지 않은 캐릭터가 있어야 편성이 성립)과 5C3=10 조합의 트레이드오프가 성립하는 최소. 5명 프로필은 데모 장면별 요구 성향(희생형·가장형·수읽기형·보수 기준선·중갑 전사)에 대응.
- C: 10명. 사망→충원·멘토링·5축 랭킹이 살아날 때 확장. 로스터 크기는 설정값.

## 8. 오케스트레이터와 조합 선택

### 8.1 유저의 조합 = 시험 문제, 오케스트레이터의 답안 = 편성·작전
- 5명(10명) 전부 전사도, 균등 분배도 유저 자유. 게임은 막지 않는다(트롤픽 완전 허용, 3.10 유지).
- 오케스트레이터는 **받은 패로 최선을 다한다.** 힐러가 없으면 속공, 습지면 경장 중심. 신체 주사위 덕에 "전사 10명"이 복사본 10개가 아니라 서로 다른 10명이 되어 역할 분담이 가능하다.
- 오케스트레이터가 평가받는 것은 좋은 조합에서의 승률이 아니라 **나쁜 조합에서의 회복력**.

### 8.2 조언 — 정리본 3.10 원설계 유지 (확정)
- 조언(추천 조합 + 승산 추정 + 근거)은 **희소**하게 발동: 미션 몇 회차 이후 + 승산 임계선 이하일 때 낮은 확률.
- 유저는 무시하고 강행 가능. 경고는 결과와 무관하게 로그에 남는다.
- 부수 효과: [조언 없음 / 수용 / 무시] 3그룹 자연 형성.
- (미확정 옵션, 14장) 승산 추정치를 정보로 상시 표시하고 개입(경고)만 희소로 분리하는 안.

### 8.3 판단 구조 (정리본 4장 유지)
- 2층: 전략 층 오케스트레이터(전투 시작 + 급변 시) / 전술 층 캐릭터 에이전트(매 턴, 방침 이탈 가능)
- 재계획 트리거: 캐릭터 이탈, 승산 임계선 붕괴, 적응 감지, 환경 변화
- 포기 판단: "어떻게 이기는가" 이전에 "싸울 가치가 있는가"
- 승산: 계산은 코드(휴리스틱), 판단은 LLM
- 환경 시스템: 규칙 엔진의 수정자, 편성 때 환경을 읽는 장면
- 적응형 상대: in-context 적응. C단계에서 랭크별 플레이북 축적.

- 하네스: JSON 스키마 강제 + 검증 + 재시도, model-agnostic, 로컬↔API 설정 교체.
- **추가 ①: Fake/Replay 어댑터.** 녹화된 로그를 재생하는 어댑터. 프론트·평가의 독립 개발과 데모 안정성(1판 빨리감기) 양쪽에 필요. LLM 장애 시 폴백.
- **추가 ②: 진영 대칭 엔진.** 7.3 참조.

## 10. 평가(Evaluation) 체계

### 10.1 A·B 단계 실험
| # | 실험 | 검증 대상 | 단계 |
|---|---|---|---|
| E1 | **조합별 오케스트레이터 ON/OFF** — 조합 3~4종(전사 몰빵/균등/방패병 몰빵/힐러 없음) × 오케스트레이터 ON vs OFF(무작위·고정 편성) 승률 | 오케스트레이터의 가치 = 나쁜 조합에서의 승률 회복 (**신규**) | A(1개) / B |
| E2 | 보스 적응 ON/OFF | 적응의 효과. B단계에서는 1판/2판이 그대로 이 대비 | B |
| E3 | 성향별 행동 분포 — 같은 전투, 성향 수치만 교체 | 다양성 = 검증된 판단 분기 | B |
| E4 | 모델 벤치마크 — 로컬 1 + API, 역할별 유효율·지연·비용 | 모델 선정 근거 | B |

- E1이 "그냥 랜덤 아니에요?"와 "오케스트레이터가 실제로 도움이 되나요?"에 동시에 답한다. 자동 대전(7.3)으로 돌린다.
- 평가 스크립트는 초기에 구축해 전 실험에서 재사용. **평가 하네스는 리팩터링 회귀 안전망이다.**

### 10.2 C 단계 실험 (정리본 7장 14개 유지 + 추가 2건)
- 원 목록 유지: 2×2 ablation, 이벤트 반응 분기, 순응률·성장 궤적, 조언 3그룹, 반사실, 캘리브레이션, 시드 분산, 육성 A/B→PvP, 밸런스 시뮬레이션, 자기대전 랭크, 평가자 일관성, 5축 분포.
- **추가 ⑮: 기대 이탈 비용 성별 대칭 검증** — 성별별 평균 이탈 턴 수 분포. 심사 질문 "여캐가 불리한가"의 답.
- **추가 ⑯: 슬롯당 사망 횟수 분포** — 신입 연쇄 사망 경로의 빈도. 죽음의 나선 감시.

### 10.3 캠페인 평가 (정리본 3.14 유지, C단계)
- 5축(생존율·피폐도·행복도·성격 변화도·성장율) 랭킹, 평가 2층 구조(지표 계산층 코드 + 평가 에이전트 LLM).
- **대체자·신입 사망은 생존율·피폐도에 동일 카운트**(6.4).
- HR/조직 언어 보류, 전이 슬라이드 한 장 — 유지.

## 11. 데모 / UI

### 11.1 구현 범위 (정리본 8.1 유지)
- 그래픽·액션 없음. 대사 + 흐름 + 내부 판정값. 정체는 **에이전트 트레이스 뷰어**.
- 참조 사례의 교훈: 프론트 폴리싱은 점수에 기여하지 않는 블랙홀이 되기 쉽다. 3패널 뷰어 밖의 연출은 하지 않는다.

### 11.2 3패널 UI (정리본 8.2 유지)
- A: 서사 스트림 + 판정 인스펙터 2패널. B: 상태 대시보드 추가.
- 원칙: 왼쪽에서 일어나는 모든 일이 가운데서 설명 가능.
- **추가: 로스터 화면에 대체자·복귀 예정 표시**(6.4). **투표 사용자용 진입 화면** — 30초 안에 "뭐가 신기한지" 전달(콘텐츠·발표 담당).

### 11.3 데모데이 10분 구성
1. 로스터 5명 관찰 → 유저 조합 선택(트롤픽 예시 1개 언급)
2. 1판 — Replay 어댑터로 빨리감기, 편성 판단 장면만 정지
3. 인터미션 — 거부 장면 **실시간**("휴식 지시 → 전투광이 몰래 훈련장"), 생애 이벤트 + 파라미터 diff
4. 2판 — 이탈·재계획·승산 붕괴·포기 구간 실시간, 인스펙터 개봉
5. 실험 차트 E1·E2 → 전이 슬라이드 1장(장애 대응) → 로드맵(C단계)
- 시드 고정·가속은 명시(정직성 원칙).
