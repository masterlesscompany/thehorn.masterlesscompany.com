## 0. 한 줄 정의와 세계관

### 0.1 한 줄 정의

**"제약 조건 하에서 자율 판단·협업·장기계획을 수행하는 멀티에이전트 시스템 — 게임을 검증 환경(testbed)으로 사용한다."**

- 유저는 캐릭터를 조종하지 않는다. 방향을 정하고, 조합을 고르고, 결과를 관찰한다.
- 캐릭터는 성격·신체·생애에 따라 따르거나 거부한다.
- 오케스트레이터는 유저가 준 로스터(좋든 나쁘든)로 최선을 찾고, 싸울 가치가 없으면 포기한다.
- **이 전부가 로그로 추적되고, 실험으로 측정된다.**

앞 절반은 게임 트레일러, 뒤 절반은 기술 문서 — 이 이중성이 프로젝트의 정체성.

### 0.2 세계관 — 1360년대, 계약이 끝난 자들

**원칙: 스토리는 시스템의 메타포다.** 규칙에 없는 설정은 쓰지 않는다.

브레티니 조약 이후. 왕들이 휴전에 서명하자 수만 명의 병사가 실직했고, 그들은 고향으로 돌아가는 대신 중대를 짜서 남았다. 사람들은 그들을 **자유중대**라 불렀고 그건 칭찬이 아니었다.

> **왕들은 브레티니에서 휴전에 서명했다. 숲은 서명하지 않았다.**

유저의 부대는 그중 가장 작은 중대다. 명단에 다섯 명이 올라 있고, 계약은 계절 단위로 들어온다. **한 계약 = 18출동.**

**마법이 없다.** 회복 주문도, 적 마법사도, 언데드도 없다. 회복은 전령관의 지혈과 봉합뿐이다.
그래서 **부상이 다음 출동으로 이월되고**, 적이 사람이 아니라서 협상도 항복도 없다.
힐러를 넣는 순간 사망률 곡선(§6.0)과 자원 딜레마(§5.0)가 동시에 무너진다.

> **이것은 문서의 약속이 아니라 CI 다.** `tests/test_boundaries.py::test_마법은_어디에도_남아_있지_않다`
> 가 `apps/arena`·`content`·`eval` 의 **식별자와 문자열 리터럴**을 AST 로 훑어 `magic`·`마법`·
> `ward`·`마도서`·`지팡이` 를 막는다. 주석은 막지 않는다 — "왜 마법을 뺐는가" 를 적을 자리가
> 필요하기 때문이다(QA 재검 C7).

### 0.3 유저의 자리 — 중대 서기

> **"당신은 칼을 들지 않는다. 장부를 든다."**

전장에서 후방과 대열을 잇는 것은 깃발과 **뿔피리**뿐이다.
**유저가 전투 중에 할 수 있는 일은 하나다 — 뿔피리. 계약 기간 동안 세 번**(§8.2).

## 3. 팀 구성 — 코어 2 + 위성 3

### 3.1 원칙
- 5명의 여유는 **코어 게임 시스템 확장에 쓰지 않는다.** 코어 상태 머신을 건드리는 기능은 통합 표면을 곱셈으로 늘린다.
- 여유는 **코어를 건드리지 않고 코어의 출력(로그)을 소비하는 일**에 쓴다: 평가, UI, 콘텐츠, 배포.

### 3.2 역할
| 역할 | 담당 범위 |
|---|---|
| **코어 A** | 규칙 엔진(순수 도메인), 하네스(스키마·검증·재시도·폴백), Fake/Replay 어댑터, 진영 대칭 전투 엔진 |
| **코어 B** | 오케스트레이터·캐릭터 에이전트 프롬프트, 재계획 트리거, 승산 휴리스틱, 보스 in-context 적응 |
| **평가·실험** | 트레이스 스키마 소유자, 실험 러너, 분포 차트, 모델 벤치마크 |
| **프론트·배포** | 3패널 트레이스 뷰어, 실도메인 배포, 투표 사용자 진입 화면 |
| **콘텐츠·발표·PM** | 세계관, 캐릭터 프로필, 이벤트 스키마, 시드 시나리오, 발표자료 |

### 3.3 첫 이틀의 계약 — 트레이스 스키마 (완료)

**DB 도 ORM 도 없다. 트레이스 이벤트 스키마가 계약이다.**
`apps/arena/domain/entities/trace_event.py` 의 `KINDS` **29종**이 정본이고
`frontend/lib/trace.ts` 가 미러한다. 양쪽이 같은 샘플(`docs/trace-samples/one-run.jsonl`)을 읽어
계약이 갈라지지 않는다.

- `kind` 는 **추가만** 한다. 이름을 바꾸거나 지우면 프론트와 실험이 동시에 깨진다.
- `payload` 에는 **판단의 입력과 내역을 전부** 싣는다. 결과만 남기면 인스펙터가 "왜"를 못 보여준다.
- **샘플이 낡았는지 묻는 테스트가 있다** — `test_샘플_트레이스가_낡지_않았다` 가 지금 코드가 만드는
  판정 뷰와 커밋된 파일을 비교한다. 그리고 `KINDS` 중 샘플이 못 덮는 종류를 **명시**한다
  (인터미션 8종만 제외 — 샘플은 `intermission=False` 로 돈다).

### 3.4 검증 날
- 9/20 앞 **1일**, 10/17 앞 **2일**은 새 기능 없이 "만든 것이 도는지만 확인하는 날".
- 통합 디버깅 30% 예약.

## 4. 캐릭터 시스템

### 4.1 생성 — 탄생과 방향

```
[1] 지급     : 로스터 5명. 각자 신체 주사위 1회 굴려진 상태로 지급
[2] 관찰     : 유저가 키·체형·몸무게·(MBTI 표기)를 본다
[3] 방향 결정: 유저가 ① 능력치 초기 포인트 18점 ② 병과 ③ 성별 을 정한다
[4] 이후     : 유저 손을 떠난다. 세부 육성·빌드는 AI, 순응 여부는 캐릭터
```

- **주사위는 탄생 1회 한정.** 신체는 이후 변하지 않는다.
- **"육각형이 좋은 게 아니다."** 신체–병과–능력치의 **정합**이 강함을 만든다.
- **병과는 중복 가능하다.** 다섯을 전부 중장병으로 뽑아도 게임은 막지 않는다(§8.1).
  막는 것은 총량(18점)·상한(20)·출전 인원뿐이고, 나머지는 **효율 페널티로 답한다**(§4.3).

#### 병과 5종 — 실제 병과 (구현됨, 마법 계열 없음)

| 병과 | 코드 키 | 주 능력치 | 무기 | 전장 역할 |
|---|---|---|---|---|
| **중장병**(Man-at-arms) | `warrior` | 힘·민첩 | 장창·대검·전투 도끼·워해머 | 돌파·백병 |
| **방패병**(Pavisier) | `defender` | 체력·힘 | 타워 실드·방패와 검 | 저지·엄호 |
| **장궁병**(Longbowman) | `archer` | 민첩 | 장궁·단궁·석궁 | 원거리 제압 |
| **약탈병**(Brigand) | `rogue` | 민첩·행운 | 단검·투척 나이프 | 정찰·측면·기습 |
| **전령관**(Herald) | `bard` | 지혜·지능 | 나팔·단검과 붕대 | 사기·응급·신호·운반 |

**전령관은 장식이 아니다.** 사상자를 세고, 지혈·봉합하고, **뿔피리를 분다**(§8.2).

전령관 없는 편성의 대가: **후퇴 신호 1턴 지연**(구현됨) / 부상 이월 / 회수·운반 미션 페널티.

> **전령관 판정은 병과로 한다.** 한때 "나팔을 들었는가"(`Equipment.is_horn`)로 판정했더니,
> 전령관에게 힘을 12 이상 찍으면 `choose_build` 가 「단검과 붕대」를 쥐여 주어 **육성이 병과 능력을
> 빼앗았다** — 화면은 "전령관 있음", 엔진은 아니라고 했다. 기획서가 말하는 것은 역할이지
> 물건이 아니다(QA 재검 R5).

### 4.2 능력치 6종 — "모든 속성은 판단 분기를 만들어야 한다"

| 능력치 | 뜻 | 무엇을 바꾸는가 | 관할 |
|---|---|---|---|
| 힘 | 근력 | 물리 피해, 중량 장비 효율 | 규칙 엔진 |
| 민첩 | 몸놀림 | 명중·회피, 행동 순서 | 규칙 엔진 |
| 체력 | 버티는 힘 | HP, 스태미나, 피로 회복 속도 | 규칙 엔진 |
| 지능 | 똑똑함 | 숙련 성장률(육성 효율), 장비 운용 효율 | 규칙 엔진 |
| **지혜** | 판단력 | **캐릭터 에이전트에 주입되는 정보의 해상도** — 낮으면 아군 상태·적 패턴이 프롬프트에서 가려진다 | 프롬프트 조립 |
| 행운 | 운 | 실행 판정·치명타 **굴림에만** 소폭 보정. 판단 로직 미개입 | 규칙 엔진 |

- **지능은 수치를 올리고, 지혜는 볼 수 있는 것을 늘린다.** 구현은 프롬프트 필드 마스킹.
- **행운은 판단에 개입하지 않는다** — `tests/test_boundaries.py` 가 `domain/services/judgment` 의
  `luck` 접근을 막는다. 개입시키면 "그냥 랜덤 아니에요?"의 근거가 되고 §10 실험이 오염된다.
- 기본 8, 자유 배분 **18점**, 상한 20. 한 능력치 몰빵(8+12=20)이 가능해야 몰빵 실험이 성립한다.

### 4.3 신체 (주사위) vs 능력치 (포인트) — 경계

| | 신체 | 능력치 |
|---|---|---|
| 결정 | 탄생 시 주사위 1회 | 유저 포인트 |
| 변화 | **불변** | 성장 |
| 역할 | **효율 스펙트럼** — "장착 가능하나 명중 -25%, 스태미나 1.2배" | **수치** |

기준: **훈련으로 변하는 것은 능력치, 타고나서 안 변하는 것은 신체.**

트롤픽(150cm 마른 몸에 판금 + 장창)도 장착된다. 페널티는 `resolution.modifiers` 에
`[['무게 미달',-10], ['키 미달',-25], ['힘 미달',1.2]]` 로 **이름과 값이 남는다.**

### 4.4 성별
- 유저가 선택한다.
- **전투·능력치·판단 엔진에 영향 0.** 표현 레이어와 생애 이벤트 사유에만 관여한다.
- **CI 가 강제한다** — `domain/services/{rules,battle,judgment}` 와 `app/use_cases/intermission`
  은 `gender` 를 읽지 않는다. 허용은 서사 표기(`agents/narration.py`)와 리플레이 기록
  (`runner.py`) 둘뿐이고, 둘 다 판정이 아니다.

### 4.5 성향 4축과 MBTI
- 판단 축 4개: 위험 성향 / 협동 성향 / 계획 성향 / 희생 수용도 — LLM 프롬프트 관할
- 내부는 수치, 외부 표현은 MBTI 스타일. **프롬프트에 MBTI 문자열이 없다**(CI 강제).
- **성향은 지급 시 시드로 결정, 유저 불가.** 유저가 정하면 실험 변수가 오염된다.

|---|---|---|---|
| **방향** | 능력치 6종 | **유저** | 출동 종료 시 성장 포인트(→은화) 지급. **은행 가능** |
| **세부** | 숙련·빌드 | **AI** | 신체·능력치·병과를 보고 판단 |
| **통제 밖** | 컨디션·성격·관계 | **캐릭터** | 순응/거부, 생애 이벤트 |

- 역성장은 **숙련·컨디션에만** 걸린다. **유저가 찍은 포인트를 시스템이 뺏지 않는다**(CI 강제 —
  `Stats` 에 감소 경로가 없다).

### 5.0 보상 — 자원 3종 + 개입 1종

| 자원 | 용도 | 상태 |
|---|---|---|
| **은화** | ① 훈련 ② **회수 비용**(§6.8) ③ 장비 | A단계는 성장 포인트로 대용 |
| **정비 행동** | 대원 1인당 1행동: 훈련 / 휴식 / 교육 / 여가 | 구현됨(인터미션) |
| **성물** | 판정 1회 개입 | B단계 |
| **뿔피리** | 계약 기간 3회, 전투 중 즉시 이탈 | **구현됨**(§8.2) |

- **은화 하나로 통합한다.** 그래야 *"토마의 회수 비용은 중장병 둘의 한 계절 훈련이고, 출동 한 번이다"*
  같은 딜레마가 성립한다. 은화가 아직 없는 A단계는 **누적 성장 포인트**를 그 자리에 쓴다 —
  `invested_of()` 의 몸통만 바뀌고 비율과 호출부는 그대로다.
- **성물은 기적을 일으키지 않는다.** advantage 를 줄 뿐이며, 이것이 마법 배제의 경계선이다.

### 5.1 육성 턴
- 유저: 카테고리 지시(교육/훈련/휴식/여가)
- 순응 판정(성격 가중치 기반 결정론적 확률) → 순응 / 부분 순응 / 거부
- 실행 판정(성실→advantage, 피로→disadvantage)
- 거부 시 LLM 이 대체 행동 서사 생성("훈련장 대신 술집") + 결과도 파라미터로 귀결
- 연구 질문: **"항상 순응하는 캐릭터가 최강인가?"**

## 6. 로스터 생애 주기

```
탄생(주사위 1회) → 방향 결정(유저) → 재적
  → [쓰러짐] → [부상]   → 회복(1~2 출동 능력 저하) → 재적
             → [끌려감] → 회수 결정(유저) → 성공 시 재적 / 미지불·실패 시 상실
             → [사망]   → 충원(주사위) → 재적   ※ 사망 = 소멸
  → [이탈: 복귀 예정] → 충원 → (대체자 사망 → 신입) → 복귀 → 재적
  → [이탈: 영구]       → 충원 → 재적
```

**구현 현황은 §14.2 에 있다.** 쓰러짐 3분기·회수·사망은 돌아가고, 이탈·충원·대체자·복귀는
아직 타입만 있다 — 누락이 아니라 §12 절단선의 "스키마만" 이 지켜지는 상태다.

### 6.0 쓰러짐 3분기

HP 가 0 이 된 대원은 **쓰러짐** 상태가 되고, **전투 종료 시** 결과가 갈린다. HP 0 이 곧 사망이 아니다.

| 분기 | 의미 | 이후 |
|---|---|---|
| **부상** | 회복 가능 | 다음 1~2 출동 능력 저하 |
| **끌려감(Taken)** | 굴로 끌려감. **살아 있다** | 유저가 회수 여부를 결정(§6.8) |
| **사망** | 소멸 | 부활 없음 |

**사이클별 확률** (`balance.CASUALTY_TABLE` — 수치 단일 출처)

| 구간 | 국면 | 부상 | 끌려감 | 사망 |
|---|---|:-:|:-:|:-:|
| 1~5 | 봄 · 고블린 | 97% | 3% | **0%** |
| 6 보스 | 성장기 | 85% | 13% | 2% |
| 7~11 | 여름 · 놀 등장 | 70% | 22% | 8% |
| 12 보스 | 성체 | 60% | 25% | 15% |
| 13~17 | 가을 · 오크 등장 | 55% | 25% | 20% |
| 18 보스 | 킹 | 50% | 25% | 25% |

**1~5 는 사망 0% 고정이다.** 첫 상실은 7~11 의 끌려감으로, **죽음이 아니라 선택으로** 온다.

**판정은 굴림과 경계를 함께 남긴다.** 이 판의 가장 무거운 판정이 결과만 남기면 그냥 랜덤과
구별되지 않는다 — `casualty` payload 에 `roll` 과 누적 경계가 실리고, 인스펙터가
「84 / 100 → 부상 ≤85 · 끌려감 ≤98 · 사망 ≤100」으로 보여준다.

### 6.1 슬롯 상태 모델
- 슬롯 필드: `점유자`, `휴직 중 원소유자`, `점유자 유형`(원소유자 / 경력 대체자 / 신입)
- 로스터 상한은 항상 N. 대체자가 자리를 점유하므로 초과가 없다.

### 6.2 이탈 — 이벤트가 아니라 판단
- 이탈 사유는 생애 이벤트 카테고리로 생성된다. **성별별 사유 목록은 다를 수 있다.**
- 이탈 여부와 **복귀 시점은 캐릭터가 판단**한다. 페널티가 아니라 **에이전트 판단 사례**.
- **기대 이탈 비용 성별 대칭**을 시뮬레이션으로 튠한다(§10.2 ⑮).

### 6.3 충원 — 주사위
- **주사위 높음** → 경력자(고정 스펙). **낮음** → 신입(생성 절차 재사용). **리롤 없음.**
- **경력자도 팀 자산은 0.** 관계·신뢰·상대 정보는 없다.
- 주사위에 사기·승률 보정을 넣지 않는다 — 넣으면 죽음의 나선이 가속된다.

### 6.4 대체자
- **대체자에게 찍은 성장 포인트는 탈퇴 시 함께 사라진다.** 실험 레버이므로 화면 표시가 필수.
- **대체자 사망 시 → 신입 고정 충원.** 대체자·신입의 사망도 사기·생존율에 동일 카운트한다 —
  빠지면 "대체자는 소모품" 이 최적 전략이 된다.

### 6.5 복귀
- 원소유자 복귀 → 현재 점유자 탈퇴. 능력치 유지, 관계·신뢰는 공백에 비례해 감쇄.
- **성격 변화 트리거를 복귀 시점에 건다.**

### 6.6 사망
- 완전 소멸, 부활 없음. 장애·트라우마·사기 하락·관계 파급.

### 6.7 이벤트 스키마 — effect 타입
```
파라미터 변경 | 결장(N턴) | 이탈(복귀 예정 / 영구) | 충원(주사위 / 신입 고정)
| 복귀(점유자 탈퇴) | 사망 | 쓰러짐(부상 / 끌려감 / 사망) | 회수(성공 / 실패)
```
**현재 구현은 `파라미터 변경` 과 `쓰러짐` 둘이다.** 나머지는 §14.2.

### 6.8 회수 — 끌려간 대원을 다시 데려오는가

**몸값은 은화만 태우지만, 회수는 은화와 출동 슬롯을 동시에 태운다.**

| 항목 | 내용 |
|---|---|
| **회수 비용** | 대원의 누적 투자 × 0.6 (안내인·횃불·사냥개) |
| **추가 비용** | **출동 슬롯 1** — 사이클의 미션 하나가 회수 출동으로 대체된다 |
| **지불 시** | 회수 미션 개방. 성공 시 복귀, 정신피로 +25, 신뢰 상승 |
| **회수 실패 시** | 은화·슬롯 소모 + 대원 상실. 적에게 학습 카드는 제공됨 |
| **미지불 시** | 영구 상실 + 보스에게 **「섭식」 카드 1장**(§8.4) + 18회차에 장비가 오크에게(§8.5) |
| **기한** | 다음 보스전까지. **넘기면 자동 미지불** |

**회수는 보장된 거래가 아니다.** 돈을 내도 실패할 수 있고, 실패하면 계약 진도까지 잃는다.

**A단계는 결정을 기록하는 데까지다.** 회수 출동 개방은 B단계다 — 그리고 **화면이 그 사실을
결정 전에 말한다**: *"지금 정하는 것은 회수를 **시도할지**다. 회수 출동은 다음 계약에 열린다."*
말하지 않으면 "돈을 냈는데 아무 일도 안 일어났다" 가 된다(QA P).

**값과 남은 시간을 보여주고 묻는다.** 비용은 러너가 계산하고 기한은 어댑터만 아는데, 한때 훅이
비용을 받아 그대로 버려서 **유저가 값을 모른 채 결정했다**(QA L). 지금은 물음 이벤트가
`awaiting_input · members · costs · timeout_s` 를 싣고 패널이 카운트다운을 보여준다.

## 7. 미션·캠페인 구조

### 7.1 계약 = 18출동, 3사이클

```
[1][2][3][4][5]      ⟦6 · 성장기⟧   봄 · 고블린 · 사망 0%
[7][8][9][10][11]    ⟦12 · 성체⟧    여름 · 놀 등장 · 끌려감 본격화
[13][14][15][16][17] ⟦18 · 킹⟧     가을 · 오크 등장 · 결전
```

**보스 셋은 다른 놈이 아니라 같은 놈이 자란 것이다**(§8.4).

**왜 4판이 아니라 5판인가.** 사이클 하나 안에서 **생애주기가 한 바퀴 돌아야** 한다 —
이탈 → 충원 → 적응 → 복귀. 4판이면 떠난 다음 판이 바로 보스전이라 대체자가 검증될 자리가 없다.

**에피소드 길이는 파라미터다.** `content/missions.py` 의 **리스트 길이가 N** 이고, 러너는 N 을
모른다. 콘텐츠가 늘면 코드를 안 고치고 늘어난다.

| 단계 | N | 구조 |
|---|---|---|
| A 제출본 | **1~2판** | 7회차 야습 + 6회차 성장기 보스전 |
| B 데모데이본 | **5~6판** | 봄 사이클 전체 + 6회차 보스전 |
| C 정식 | **18판** | 3사이클 전체 |

**호출 예산은 전투 한 판 기준이다** (1판 = 100~300 호출). 계약이 길어지면 예산도 같이 늘어난다 —
`build_harness(missions=N)` 이 `MAX_CALLS × N` 을 잡는다. 한때 예산이 **런당 하나**여서
18출동을 흉내 내면 8회차부터 모든 판단이 조용히 Fake 로 떨어졌고, 그때 `calls_used` 가 0 을 찍어
**"호출 300 이하" 검사가 모델을 아예 안 쓴 판에서 가장 예쁘게 통과했다**(QA P0-F).
지금은 예산 밖 호출도 세고 `mission_end.fallbacks` 가 판마다 폴백 횟수를 싣는다.

**호출량 완화 장치**
- 유형별 턴 예산 차등: 정찰 3~5 / 교전 6~8 / 호위 8~10 / 보스 12~15
- 정원이 곧 호출 배수 → 정원 5 미션은 사이클당 1회
- 비전투 구간은 규칙 엔진 + 서사 1회 호출
- **적 개체 판단에 LLM 을 쓰지 않는다.** 수하는 고정 정책(호출 0), LLM 은 보스에만

### 7.1a 미션은 12개를 손으로 만들지 않는다 — 3축 조합

미션은 **목표축 · 환경축 · 제약축** 3축의 조합으로 생성한다.

| 종 | 전술 지문 | 부수는 슬롯 | 유저에게 시험하는 것 |
|---|---|:-:|---|
| **고블린** | 다수·매복. 열세를 감지하면 도주하고 다시 모인다 | D 소탕 | 광역 처리, 추격 손익 |
| **놀** | 기동·측면. **부상자와 낙오자를 우선해서 문다** | C 호위 | 보호 대상 지정, 희생 수용도 |
| **오크** | 소수 정예. 정면 돌파. 전리품을 걸친다 | B 교전 | 방패병의 값, 저지 판단 |
| **미노타우루스** | 위 셋을 거느린다. 3형태로 성장 | 전부 | 보스 |

**언데드·악마·이형·적 마법사를 넣지 않는다.** 취향이 아니라 에셋 문제다 — 전부 살과 뼈라
정지 스프라이트 + 상태 오버레이만으로 성립한다.

### 7.1b 결과 5등급

| 등급 | 판정 |
|---|---|
| 완전 성공 | 승리 + 아무도 안 다침 |
| 성공 | 승리, 부상·끌려감 있음 |
| **철수** | 목표 미달, **전원 생환**. 중대장의 후퇴 판단 또는 뿔피리 |
| 실패 | 퇴각, 끌려감 발생 |
| 참사 | **사망 발생** |

**「철수」가 벌점이 아닌 것이 핵심이다.** 포기 판단을 시스템이 처벌하면 §8.3 이 죽는다.

> **부상자가 있어도 「철수」다** — 2026-09-09 팀 결정 #13(§14.1). 뿔피리를 불어 전원 데리고
> 나온 판이 부상 때문에 「실패」가 되면 이 조항이 무의미해진다.

### 7.2 출전 인원 — 미션별 가변
- 미션마다 출전 가능 인원이 다르다. **유저가 조합을 선택**한다.
- A·B: 로스터 5, 출전 1~3. C: 로스터 5, 출전 1~5.

### 7.3 PvP — 위치 이동
- **플레이어 미션으로는 C단계.** **평가 도구로는 A단계부터** — 자동 대전이 데이터 생성기다.
- 전제: 규칙 엔진이 **진영(faction) 대칭**. 보스전과 PvP 가 같은 코드 경로.

### 7.4 로스터 규모
- A·B·C 모두 **5명 / 출전 3**. 18출동 안에서 사망·끌려감·충원이 돌면 인원이 아니라 **교체율**이
  서사를 만든다.

## 8. 오케스트레이터와 조합 선택

### 8.1 유저의 조합 = 시험 문제, 오케스트레이터의 답안 = 편성·작전
- 전원 중장병도, 균등도 유저 자유. **게임은 막지 않는다.**
- 오케스트레이터가 평가받는 것은 좋은 조합에서의 승률이 아니라 **나쁜 조합에서의 회복력**.
  §10.1 이 이 문장을 직접 잰다.

### 8.2 뿔피리 — 유저의 유일한 전투 중 개입

**계약 기간 동안 세 번.**

- **불면**: 즉시 전원 이탈. 전멸은 피하지만 목표는 실패하고 보수는 없다. 등급 「철수」.
- **불지 않으면**: 중대장이 스스로 판단한다. **물러날 줄 아는가.**
- **뿔피리는 전령관이 분다.** 전령관이 없으면 신호가 **한 턴 늦는다** — 그 한 턴에 누가 쓰러질 수
  있다. 이것이 병과의 값이다.

**세 번인 이유는 설정이 아니라 설계다.** 무한이면 유저가 조종하는 게임이 되고(§0.1 위반),
0 이면 관전이 된다.

**구현이 지켜야 하는 것 — 전부 회귀 테스트로 굳혔다**

| 규칙 | 왜 |
|---|---|
| 전투 중에만 받는다 | 인터미션·회수 대기 중에 받으면 신호가 다음 판 1턴에 엉뚱하게 터진다 |
| 판이 끝나면 안 닿은 신호를 버린다 | 판 경계는 러너가 게이트로 알린다. "1턴이면 버린다" 로 막던 때는 **정상 입력까지 먹었다**(QA 재검 R2) |
| 대기 중인 신호가 새 입력보다 **먼저** | "안 울렸네" 하고 다시 누르면 대기 신호가 덮여 **충전 셋을 다 쓰고도 한 번도 안 울렸다**(R3) |
| `horn` 이벤트는 **닿은 턴에 하나만** | 지연을 따로 내면 리플레이가 그 턴에도 분다 |
| 닿기 전에 판이 끝나면 `delivered: false` | 흔적 없이 사라지면 유저는 "전원 살려 나왔다" 고 믿는다 |
| 리플레이 런은 받지 않는다 | 소비자가 없어 신호가 영원히 남고 이후 요청이 전부 409 가 됐다(R4) |
| 리플레이는 **회차와 원래 턴**으로 재생 | 6회차 뿔피리가 7회차에서 터지고, 왕복마다 1턴씩 밀렸다(R1) |
| 화면은 200 에 도착을 단언하지 않는다 | "신호를 보냈다" 까지만. 실제 문구는 `horn` 이벤트가 쓴다 |

이 장치가 만드는 실험이 **E7**(§10.1) 이다 — **"AI 가 사람보다 물러날 때를 잘 아는가."**

### 8.2a 조언 — 희소
- 조언(추천 조합 + 승산 추정 + 근거)은 미션 몇 회차 이후 + 승산 임계선 이하일 때 낮은 확률로.
- 유저는 무시하고 강행 가능. 경고는 결과와 무관하게 로그에 남는다.

### 8.3 판단 구조
- 2층: 전략 층 오케스트레이터(전투 시작 + 급변 시) / 전술 층 캐릭터 에이전트(매 턴, 이탈 가능)
- 재계획 트리거: 캐릭터 이탈, 승산 임계선 붕괴, 적응 감지, 환경 변화
- 포기 판단: **"어떻게 이기는가" 이전에 "싸울 가치가 있는가"**
- 승산: **계산은 코드, 판단은 LLM.** 이 경계가 인스펙터의 "왜 그랬는가"를 만든다
- **최소 교전 턴 하한**: 보스전 8턴 / 일반 3턴 (팀 결정 #5). **미구현** — §14.3

### 8.4 적은 어떻게 강해지는가 — 학습 카드 4대 출처

**판타지 초능력이 아니다. 그것은 유저가 남긴 것을 먹고 자란다.**

| 종 | 출처 | 발생 조건 | 유저의 차단 수단 |
|---|---|---|---|
| **고블린** | **척후 관찰** | 정찰 미션 실패 | 해당 미션 성공 |
| **놀** | **탈주 추적** | 정신피로 임계 초과 대원의 이탈 | 휴식·급료 배분 |
| **오크** | **전리품** | 미션 후 시신·장비 미회수 | 회수 조건 달성 |
| **미노타우루스** | **섭식** | 끌려간 대원을 **회수하지 않음** | 은화 + 출동 슬롯 지불 |

**유저가 학습을 억제하는 수단이 전부 자원 결정과 연결된다.**

| 형태 | 회차 | 카드 슬롯 | 학습 범위 |
|---|:-:|:-:|---|
| 성장기 미노타우루스 | 6 | 3 | 1~5 에서 가장 빈번한 패턴만 |
| 성체 미노타우루스 | 12 | 5 | 누적 + 회피 봉쇄 |
| 미노타우루스 킹 | 18 | 7 | 누적 + 개인 단위 대응 + 전리품 편제 |

**생성은 결정론 + LLM 2층이다.**
```
[집계 · 코드]  전투 로그 → 패턴 지표 → 상위 N개
[매칭 · 코드]  카운터 카드 풀에서 결정론적 선택
[전술 · LLM]   보유 카드를 언제 어떻게 쓸지 in-context 판단
```
**집계도 매칭도 결정론이다.** 그러지 않으면 "보스가 배웠다" 가 아니라 "보스가 굴렸다" 가 되고,
인스펙터가 출처를 가리킬 수 없다.

**카드마다 출처 라운드·인물·종이 링크된다**(§11.2). 라운드가 없으면 판을 넘는 학습이 아니라
그냥 표시다 — `ActionRecord.mission` 이 기록에 회차를 찍어 나른다.

> **화면은 걸린 것을 그대로 말한다.** 「섭식」의 계승은 **같은 병과가 지금 판에 서 있을 때만**
> 발동하는데, 기본 로스터는 5명 5병과에 출전 3명이라 중복 병과가 구조적으로 어렵다.
> 걸 데가 없으면 `applied` 가 비고 패널이 *"이 판에는 그 병과가 없어 아직 쓰지 못한다"* 고
> 말한다 — `boss_adapt` 의 `no_change` 와 같은 원칙이다(QA 재검 R20).

### 8.5 그것에게는 이름이 없다

미노타우루스는 고유명을 갖고 시작하지 않는다. **대원들은 그것이 처음 데려간 사람의 이름으로
그것을 부른다.**

- 첫 「끌려감」 대원의 이름이 그대로 보스 호칭이 된다 — "토마를 데려간 것"
- **회수에 성공했더라도 호칭은 남는다.** 대원들은 잊지 않는다
- 유저마다 보스 이름이 다르다. 로그에서 생성되므로 구현 비용은 문자열 하나

**18회차 전리품 편제**: 회수하지 않은 장비가 실제로 적에게 장착된다. 진영 대칭 엔진(§7.3)을
그대로 쓰므로 신규 에셋 0 장이다.

## 9. 에이전트·소프트웨어 아키텍처

### 9.1 계층 — 클린 아키텍처 3층 + BC 밖 셋

```
backend/
├── core/        BC 밖 전역 인프라
├── content/     BC 밖 세계관 데이터 — 로스터·병과·몬스터·환경·미션·생애이벤트·카드
├── eval/        BC 밖 실험 러너 — E1·E2·E3
├── tests/       BC 밖 경계 테스트
└── apps/arena/  BC #1 — 에르덴 용병단 자동대전
    ├── domain/    최내층. 표준 라이브러리만
    ├── app/       유스케이스 — runner · battle_setup · learning_cards · agents · intermission
    └── adapter/   최외층 — inbound/api · outbound/{repositories,sinks,strategies}
```

**화살표는 안쪽으로만 간다. `tests/test_boundaries.py` 가 AST 로 강제한다** — 문서가 아니라 CI 다.

| 규칙 | 무엇을 막는가 |
|---|---|
| `domain` 은 바깥을 import 하지 않는다 | 최내층의 의존성 역전 |
| `app` 은 `adapter` 를 import 하지 않는다 | 유스케이스가 기술을 고르는 것 |
| **`content` 는 유스케이스를 import 하지 않는다** | 세계관 데이터가 유스케이스에 묶이면 밸런스 튠이 코드 수정이 된다 |
| 안쪽은 인프라 프레임워크를 모른다 | 프레임워크가 도메인에 새는 것 |
| 안쪽은 `random` 을 직접 쓰지 않는다 | 결정론 파괴 |
| 성별·행운·마법 | §4.4·§4.2·§0.2 |

> `content` 규칙이 **없어서** `content/party.py` 가 `app/use_cases/agents/narration` 을
> import 하는 것이 CI 를 통과했다. 그 import 를 만든 `voice()` 의 성별 분기는 두 갈래가 **같은
> 문자열을 돌려주는 죽은 코드**였다(QA 재검 R15).

### 9.2 포트와 어댑터
**포트는 구현이 둘 이상일 때만 만든다.** 현재 넷:

| 포트 | 약속 | 구현 |
|---|---|---|
| `Dice` | 시드 고정 난수 — **같은 시드 = 같은 판** | `SeededDice` · `FixedDice` |
| `DecisionModel` | "모델이 답한다" **만**. 검증·재시도·폴백은 약속하지 않는다 | `FakeModel` · `ReplayModel` · `Harness`(데코레이터) |
| `TraceSink` | 트레이스를 받는다. 싱크 실패가 판을 멈추면 안 된다 | `ListSink` · SSE 큐 |
| `RunStore` | 런 저장·조회 | `JsonlRunStore` |

**모든 모델 호출은 하네스를 지난다** — 스키마 강제·검증·재시도·폴백·호출 계수.

### 9.3 재현의 전제
**같은 시드 + 같은 트레이스 = 같은 판.** `ReplayModel` 이 녹화된 판단을 순서대로 돌려주고
`SeededDice` 가 같은 굴림을 낸다. **유저 입력도 재생한다** — 뿔피리(회차·원래 턴)와 회수 결정을
트레이스에서 복원한다. 이 둘이 깨지면 §10 의 비교가 무의미해진다.

교차 프로세스 검증: `PYTHONHASHSEED` 5종 × 샘플 생성 sha256 동일. 조합 4 × ON/OFF × 시드 10 ×
6출동, 뿔피리·회수·카드 전부 켠 **27,954 이벤트**가 해시시드 4종에서 sha256 동일.

## 10. 평가(Evaluation) 체계

**실험은 후처리만으로 계산된다.** 러너를 고쳐야 지표가 나오면 실험이 코어를 건드리게 된다.

### 10.0 지표가 재는 층 — 판 단위와 계약 단위

한때 지표가 **마지막 미션의 승패만** 승률로 썼다. 감독이 판을 길게 끌면 쓰러진 사람이 늘고,
그가 끌려가면 다음 판을 둘로 간다 — 그 연쇄의 끝만 보면 **E1 은 감독이 아니라 직전 판의 끌려감
주사위를 잰다**(QA P0-E). 지금은 두 층을 따로 낸다.

| 층 | 지표 |
|---|---|
| **판 단위** | `win_rate`·`retreat_rate`·`loss_rate` (계약 안 **모든** 판) · `grade_share`(5등급) |
| **계약 단위** | `clear_rate`(전 판 목표 달성) · `home_rate`(아무도 죽지도 끌려가지도 않음) |
| 사상 | `avg_injured` · `avg_taken` · `avg_dead` |
| 비용 | `avg_peak_mission_calls` · `avg_contract_calls` · `max_calls` |
| 적응 | `adapt_no_change_rate` · `focus_follow_rate` |

**완주율 하나로는 §8.1 을 반증한다.** 감독이 목표를 포기하고 전원 데리고 나온 판이 전부 벌점이
되기 때문이다 — 「철수」는 벌점이 아니다(§7.1b). 그래서 **생환** 축을 함께 낸다.

### 10.1 A·B 단계 실험

| # | 실험 | 검증 대상 | 단계 |
|---|---|---|---|
| **E1** | 조합별 오케스트레이터 ON/OFF — 중장병 몰빵 / 균등 / 방패병 몰빵 / 전령관 없음 | **나쁜 조합에서의 회복력** | A · B |
| **E2** | 보스 적응 ON/OFF | 적응의 효과 | B |
| **E3** | 성향별 행동 분포 — 같은 전투, 성향 수치만 교체 | 다양성 = 검증된 판단 분기 | B |
| E4 | 모델 벤치마크 | 모델 선정 근거 | B |
| **E7** | **뿔피리 사용 시점** — 유저의 뿔피리 vs 중대장의 자율 후퇴 | **"AI 가 사람보다 물러날 때를 잘 아는가"** | B |
| E8 | 회수 결정과 완주율 | 자원 딜레마가 양방향인지 | C |

#### E1 실측 — 시드 200, Fake 모델 (2026-09-09)

| 조합 | 완주 ON/OFF | 생환 ON/OFF | 완주 짝비교 | 생환 짝비교 |
|---|---|---|---|---|
| 중장병 몰빵 | 34% / 44% | 57% / 55% | ON만 17 · OFF만 39 · p=0.0046 | p=0.6570 (잡음) |
| 균등 | **74% / 8%** | **90% / 45%** | ON만 134 · OFF만 1 · **p=0.0000** | **p=0.0000** |
| 방패병 몰빵 | 0% / 0% | 36% / 28% | p=1.0000 | p=0.1100 |
| **전령관 없음** | **21% / 0%** | **66% / 42%** | ON만 42 · OFF만 0 · **p=0.0000** | **p=0.0000** |

**§8.1 이 지지된다** — 「전령관 없음」이라는 나쁜 조합에서 감독이 두 축 모두 유의하게 좋다.
「중장병 몰빵」의 완주 열세는 남아 있고(p=0.0046), **튜닝으로 지우지 않고 측정된 사실로 둔다.**

> **이 표에 오기까지**: 처음 재니 중장병 몰빵이 ON 2% / OFF 44% 였다. 원인은 감독이 아니라
> **Fake 단장의 규칙 한 줄**이었다 — 보스 없는 판에서 「가장 약한 적」 지목이 후열 투석수를 잡아
> 근접 타격이 되돌려졌고(30시드 264회), 지목이 광역 기술을 잡아먹었다. 감독 OFF 는 지목이 없어
> **우연히** 광역을 골랐다. 지목을 닿는 적 안으로 제한하고 적 3기 이상이면 광역을 우선하게
> 고친 뒤가 위 표다(팀 결정 #14). **A/B 로 원인을 고정한 뒤에 고쳤다.**

#### E2 실측 — 시드 100

적응은 발동하고 `boss_focus` 도 바뀌는데(무효 8~13%), **승패는 ON/OFF 가 구별되지 않는다**(p=1.0).
지표 결함이 아니다 — **지목한 대상을 보스가 실제로 때린 비율이 47%** 다. 근접 보스는 전열이 살아
있는 한 후열에 못 닿는데 지목 대상은 대개 후열이다. 차트가 "적응은 무의미하다" 가 아니라
**"적응은 일어나지만 지목의 절반이 손에 닿지 않는다"** 고 말한다. 닿게 만드는 것은 밸런스 설계
변경이라 §14.3 에 있다.

### 10.2 C 단계 실험
- 2×2 ablation, 이벤트 반응 분기, 순응률·성장 궤적, 조언 3그룹, 반사실, 캘리브레이션,
  시드 분산, 육성 A/B→PvP, 밸런스 시뮬레이션, 자기대전 랭크, 평가자 일관성, 5축 분포
- **⑮ 기대 이탈 비용 성별 대칭 검증** · **⑯ 슬롯당 사망 횟수 분포**
- **⑰(E5) 배분 정책 3그룹** · **⑱(E6) 패턴 분산도 vs 보스 강도**
- **밸런스 목표**: 계약 완주율 60~70%, 평균 사망 1.5명, 회수 성공률 60~70%

### 10.3 캠페인 평가 (C단계)
5축(생존율·피폐도·행복도·성격 변화도·성장율) 랭킹, 평가 2층(지표 계산층 코드 + 평가 에이전트 LLM).

### 11.1 구현 범위
- 그래픽·액션 없음. 정체는 **에이전트 트레이스 뷰어**. 3패널 밖의 연출은 하지 않는다.

### 11.2 3패널 UI
- 서사 스트림 + 판정 인스펙터 + 상태 대시보드.
- **원칙: 왼쪽에서 일어나는 모든 일이 가운데서 설명 가능하다.**
  이 약속을 지키려고 `horn`·`recovery`·`boss_named`·`casualty` 에 전용 뷰를 붙였다 —
  강조 스타일만 주고 날 JSON 을 뱉으면 **가장 눌러 보고 싶은 줄이 가장 불친절해진다**(QA 재검 R8).
- **뿔피리 버튼** — 전투 화면 상시 노출, 잔여 횟수, 못 부는 이유 표시.
- **학습 카드 패널** — 보스전 시작에 펼쳐지고 출처 라운드·인물·종이 링크된다. 걸린 것이 없으면
  그렇게 말한다.
- **회수 결정 화면** — 1인 비용·합계·남은 시간 카운트다운 + "회수 출동은 다음 계약에 열린다".
- **결산 화면** — 5등급 · 부상/끌려감/사망 3행 · 회수 결정 · 보스 호칭 · 모델 호출(폴백 포함).

**박자.** Fake 는 한 판을 0.1초에 끝낸다 — 그러면 **뿔피리를 물리적으로 누를 수 없다.**
기본 박자는 Fake 0.2초/판단, 실모델 0(이미 느리다), 환경변수(`RPG_PACE_S`)가 이긴다.
테스트는 `conftest.py` 가 0 으로 못박는다.

## 15. 리스크 및 예상 질문

| 질문 | 답 |
|---|---|
| "그냥 랜덤 아니에요?" | 인스펙터 개봉. 결정론적 가중치 → 수치 → 판단 축. 행운은 판단에 미개입. **같은 시드로 다시 돌려 보여준다** — 교차 프로세스 27,954 이벤트 sha256 동일 |
| "유저가 할 게 없는 거 아닌가요?" | **뿔피리 3회.** 매 판 "지금인가"를 묻는다. 불지 않은 결과가 보스 이름과 학습 카드로 돌아온다 |
| "보스가 학습한다는 게 실감이 나나요?" | **카드 개봉 화면.** 출처 라운드·인물·종 링크 — "7회차에 당신이 굴에 두고 온 오드에게서" |
| "오케스트레이터가 실제로 도움이 되나요?" | E1. **나쁜 조합(전령관 없음)에서 완주 21% vs 0%, 생환 66% vs 42%, 둘 다 p=0.0000** |
| "적응이 효과가 있나요?" | **아직 승패에서는 안 보인다.** 지목의 절반이 손에 닿지 않기 때문이고, 그 숫자를 차트에 올린다. 숨기지 않는다 |
| "여성 캐릭터가 불리한 게임 아닌가요?" | 성별은 엔진 영향 0 — **CI 가 강제한다.** 이탈 사유만 다르고 기대 이탈 턴은 시뮬레이션에서 동일하게 튠 |
| "지혜 높으면 뭐가 달라져요?" | 프롬프트에 들어가는 정보 필드가 다르다 — 같은 상황 두 캐릭터의 입력 컨텍스트 비교 |
| "18판 다 만들었나요?" | **아니요.** 에피소드 길이는 파라미터고 A단계는 2판이다. 예산·계수는 18판을 견디고 그걸 테스트가 확인한다. 콘텐츠는 로드맵 |
| "왜 마법이 없나요?" | 힐러를 넣는 순간 사망률 곡선과 자원 딜레마가 동시에 무너진다. 부상 이월이 압박이 되려면 회복이 귀해야 한다 |
| "스토리가 시스템을 가리는 거 아닌가요?" | 규칙에 없는 설정을 쓰지 않았다. 시나리오 §6 표가 스토리→조항 대응이다 |
| "테스트가 있다는 걸 어떻게 믿죠?" | **돌연변이를 넣어 보여준다.** 예산 규칙을 옛 버그로 되돌리면 빨개지고, 마법 식별자를 넣으면 빨개지고, 계약 샘플을 안 갱신하면 빨개진다 |
