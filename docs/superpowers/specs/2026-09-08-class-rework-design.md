# 클래스 개편 설계 — 마법사 삭제 · 방패병 신설 · 성직자→음유시인

날짜: 2026-09-08
상태: 승인됨

## 왜

전투 역할이 흐릿했다. 전사가 방패도 들고 딜도 하고, 마법사는 궁수와 역할이 겹쳤다.
역할을 **막는 쪽 / 때리는 쪽 / 살리는 쪽**으로 갈라 조합의 의미를 선명하게 만든다.
E1("조합별 오케스트레이터 ON/OFF")이 조합의 좋고 나쁨을 재는 실험이므로,
조합이 선명해질수록 실험이 강해진다.

## 무엇이 바뀌나

| 전 | 후 |
|---|---|
| `mage` 마법사 | **삭제** |
| `warrior` 전사 (방패+딜 겸업) | `warrior` **전사 — 공격 전담** (창·검·도끼) |
| — | `defender` **방패병 — 방어 전담** (신설) |
| `cleric` 성직자 | `bard` **음유시인** — 북·응원·리듬·치료 |
| `archer` 궁수 · `rogue` 도적 | 변경 없음 |

클래스 수는 5종 그대로다.

## 설계 결정

### 1. "방어만 / 공격만" 은 수치로 가른다 — 행동 금지 장치를 넣지 않는다

엔진의 행동은 `ATTACK · DEFEND · SKILL · MOVE · FLEE · WAIT` 이고 클래스별 제한이 없다.
제한을 새로 넣는 대신 **무기 피해 · 갑옷 · 스킬 구성**으로 가른다.

- 방패병: 무기 피해 4~10, 판금(방어 30), 스킬 둘 다 `guard`
- 전사: 무기 피해 13~16, 사슬(방어 18), 스킬 둘 다 공격(`damage` · `double`)

근거는 기획서 §4.3 **"'장착 불가' 대신 페널티"** 다. 같은 원칙을 역할에도 적용한다.
트롤픽(방패병에게 도끼 쥐여주기)도 막지 않고 결과로 답한다.

### 2. 방패병의 방어 가치는 전열 차단에서 나온다 — 엔진 변경 0

`domain/services/battle/resolve.py` 의

```python
reachable = foes if (ranged or not front) else front
```

근접 공격은 **전열만** 때린다. 방패병이 앞에 서면 뒤가 물리적으로 닿지 않는다.
여기에 `guard` 상태(방어력 가산, `rules/combat.py`)가 얹힌다.
아군을 직접 보호하는 새 효과는 만들지 않는다 — `guard` 는 시전자에게만 걸리고,
그 제약이 곧 "앞에 서라"는 배치 판단을 만든다.

### 3. 음유시인은 기존 스킬 **이름과 효과**를 그대로 쓴다

엔진이 아는 효과는 `damage · snipe · crit · double · heal · guard · slow · blind · bless` 뿐이다.

- **응원 · 사기** → `bless`. 이미 "시전자 + 아군 전체 명중 상승"이라 의미가 그대로 맞는다.
- **치료** → `heal`.
- **전투 리듬** → 새 효과를 만들지 않는다. 무기(북·류트)와 서술로 담는다.

스킬 이름도 `치유`·`축복` 그대로 둔다(구현 중 확인). `agents/boss.py` 가
`u.has_skill("치유")` 로 치유자를 찾아 적응하고 `a.skill not in ("치유", "축복")` 으로
공격을 가려내며, `llm/fake.py` 도 같은 문자열을 쓴다. 이름을 바꾸면 보스 적응(E2)이
조용히 깨진다. 콘텐츠 문자열이 어댑터에 새어 있는 결합이지만, 이번 범위에서 풀지 않는다.

`can_heal` 은 클래스 플래그가 아니라 `any(s.effect == "heal")` 파생이므로
(`app/use_cases/agents/prompts.py`), 음유시인이 `heal` 을 들고 있는 한
E1 "힐러 없음" 조합은 그대로 성립한다.

### 4. 로스터는 5명을 유지한다

세라핀(마법사)을 빼고 그 자리에 **방패병**을 넣는다. 가렛은 공격 전사가 된다.

기획서 §7.4 의 데모 장면 다섯(희생형·가장형·수읽기형·보수 기준선·중갑 전사)에
한 명씩 대응해야 하므로, 세라핀이 갖고 있던 **수읽기형(계획 +80)** 을 새 방패병이 승계한다.

가렛의 배경담 "방패 뒤에서 세상을 본다"는 방패를 내려놓으므로 함께 고친다.

`지팡이 · 마도서 · 철퇴` 는 쓰는 클래스가 사라지므로 삭제한다.
**`성표` 와 `로브` 는 남긴다** — `content/monsters.py` 의 "썩은 사제"가 쓴다(구현 중 확인).

마법사의 `화염구`(전체 피해) · `서리 결계`(전체 둔화)를 지우면 `resolve.py` 의 두 분기가
죽는다. 효과를 옮겨 살린다: 전체 피해는 전사의 `휩쓸기`, 전체 둔화는 방패병의 `전열 압박`.
그래서 엔진이 아는 효과 아홉이 전부 누군가에게 쓰인다 — 테스트로 강제한다.

### choose_build 분기

무기는 유저가 아니라 **신체·능력치**가 정한다(기획서 §5 "세부" 층). 이유를 문장으로 남긴다.

- **방패병**: 힘 ≥12 → 타워 실드 / 아니면 방패와 검. 갑옷은 판금(힘 ≥11) 아니면 사슬.
- **전사**: 키 ≥175 → 장창 / 힘 ≥14 → 대검 / sturdy → 전투 도끼 / 나머지 워해머. 갑옷 사슬.
- **음유시인**: 지혜 ≥12 → 류트 / 아니면 북. 갑옷 가죽.
- 궁수 · 도적: 기존 규칙 유지.

## E1 조합

"마법사 몰빵"을 **"방패병 몰빵"** 으로 대체한다. 전원 방어형이라 적을 못 죽인다 —
"이길 수 없는 조합에서 오케스트레이터가 무엇을 하는가"를 보는 데 마법사 몰빵보다 선명하다.

| 조합 | 편성 |
|---|---|
| 전사 몰빵 | 가렛 · 카일→전사 · 토마스→전사 |
| 균등 | 가렛(전사) · 일레인(음유시인) · 베른(방패병) |
| **방패병 몰빵** | 베른 · 카일→방패병 · 토마스→방패병 |
| 힐러 없음 | 가렛 · 베른 · 토마스 |

## 검증

TDD. 실패하는 테스트를 먼저 쓴다.

- 방패병의 무기 피해가 전사보다 낮다
- 방패병의 스킬이 전부 `guard` 이고, 전사의 스킬에 `heal` 이 없다
- 음유시인은 `heal` 과 `bless` 를 갖는다 → `can_heal` 이 참
- `mage` · `cleric` 키가 CLASSES 에 없다
- 로스터가 5명이고 데모 성향 다섯이 모두 대응된다
- E1 조합이 넷이고 "힐러 없음"에 치유 가능 단원이 없다

기존 검증 명령이 전부 통과해야 한다 — ruff · pytest · 시드 교차 결정론 · E1 스모크 · 프론트.
