- **배포 전 안전장치를 넣었다 — 동시 런 상한 · 세션 정리 · 다중 구독 스트림**
  배포하면 누구나 POST /runs 를 반복할 수 있고 런마다 스레드 하나와 이벤트 전량이
  메모리에 남는다. MAX_CALLS 는 런 하나 안의 호출만 막는다. 동시 8판 상한(429)과
  완료 세션 TTL 을 두고, 새 런을 만들 때 훑어 치운다 — 예전에는 완료마다
  threading.Timer 를 띄웠고 런이 끝나지 않으면 영영 남았다.

  SSE 종료 센티널이 단일 소비자 전제였다. 같은 판을 둘이 보면 한쪽의 done 이
  15초 늦었다(개발 모드의 StrictMode 이중 마운트에서도 같다). 종료는 done
  플래그가 판정하고 큐는 깨우는 신호로만 쓴다.

  저장 실패를 session.error 로 남겨 화면이 안다 — 스트림은 정상으로 끝나는데
  세션이 지워지면 방금 본 판이 사라졌다.

  도주 사유에 "가족 없음" 이 붙던 것도 고쳤다. 두고 온 사람이 있을 때만 말한다.
