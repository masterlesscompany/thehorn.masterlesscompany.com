- **백엔드를 클린 아키텍처 계층으로 재배치했다**
  cloud.whoareryu/fastapi/apps/dumb_and_dumber 스켈레톤을 기준으로 backend/ 를
  BC 하나(apps/arena)와 그 안의 3층(domain → app → adapter)으로 옮겼다. 종전
  core/adapters/api 는 "안쪽 하나 · 바깥 셋" 이라 계층이 둘뿐이었고, 유스케이스와
  도메인 규칙이 같은 core/ 에 섞여 있었다. 층을 셋으로 가르면 경계 규칙도 셋이 되어
  CI 가 더 촘촘히 막는다.

  옮기면서 판단한 것 셋:

  포트를 domain/ports/ 에 뒀다. 템플릿은 app/ports/output/ 이지만 Dice 는
  domain/services 가, TraceSink 는 domain/entities/trace_event 가 의존한다.
  거기 두면 도메인이 app 을 import 하는 역전이 생긴다 — 인터페이스는 안쪽이
  소유하고 바깥이 구현한다(설계 원칙 §9).

  josa 를 app/use_cases/agents 에서 domain/services 로 내렸다. battle/resolve 가
  서사 문장을 만들며 이걸 부르는데, 받침을 보는 순수 문자열 유틸이라 도메인이 맞다.
  이 이동으로 도메인→app 역전이 사라졌다.

  dice 를 adapter/outbound/strategies 로 올렸다. 그 결과 "core 는 random 을 직접
  쓰지 않는다" 테스트의 파일명 예외(dice.py)가 없어졌다 — 이제 domain·app 에는
  결정론을 깰 경로가 구조적으로 없다.

  DB 가 없어 템플릿의 orm/·mcp/·grpc/·websocket/ 과 아직 쓰지 않는
  dependencies/·app/dtos/·domain/value_objects/·app/ports/input/ 은 만들지 않았다.
  빈 폴더는 구조가 아니라 약속이고, 지킬 수 없는 약속은 두지 않는다.

  content/·eval/·core/ 는 BC 밖에 남겼다. 세계관 데이터가 domain 안으로 들어가면
  밸런스 튠이 코드 수정이 된다(설계 §3.3).

  test_boundaries 를 3층용으로 다시 썼다. 규칙이 하나에서 넷으로 늘었다 —
  domain→바깥 금지, app→adapter 금지, 안쪽의 인프라 프레임워크 금지, 안쪽의
  random 금지. 성별·행운 격리 셋은 새 경로로 옮겼다.

  검증: ruff check·format, pytest 361 passed, 시드 교차 결정론(PYTHONHASHSEED
  0 vs 12345 동일), eval e1, 트레이스 샘플 재생성 무변화, 프론트 22 pass·tsc.

  types.py 는 쪼개지 않았다. Character(엔티티)와 Body·Stats 등 VO 가 한 파일에
  있지만, 그건 폴더 구조가 아니라 내용 리팩터링이라 따로 다룬다.
