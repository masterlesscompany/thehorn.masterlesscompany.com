- **B단계 인터미션을 구현했다 — 육성 턴 · 술집 장면 · 생애 이벤트 · 성장 포인트**
  기획서 §2 가 A→B 의 핵심 차이라고 한 것: 인터미션이 있어야 육성·거부·생애
  이벤트가 존재하고, 그 뒤에 전투가 있어야 "이벤트 → 판단 변화" 의 인과가 닫힌다.

  육성 턴은 전투의 순응 판정과 같은 원칙이다 — 코드가 결정론적 확률을 계산하고
  시드 주사위가 정한다. 모델은 거부했을 때 **무엇을 했는지**만 쓴다("훈련장 대신
  술집"). 실행 판정은 성실하면 advantage, 피로하면 disadvantage 로 굴린다(§5.1).

  생애 이벤트는 성향 4축을 바꾸고 param_diff 로 before/after 를 남긴다. 카일에게
  "아이가 앓는다" 가 뜨면 위험 -20 · 희생 -20 이고, 그 값이 다음 판의 이탈 확률로
  그대로 흘러간다. effect 는 param_change 하나만 쓴다 — 이탈·충원·복귀·사망은
  C단계이고 타입만 선언돼 있다(§6.7).

  성장 포인트는 승리 10 / 그 밖 6 이다. 패배와 후퇴에도 주는 이유는 0 이면 후퇴
  판단에 벌점이 되어 단장이 포기를 회피하게 되기 때문이다. 안 쓴 것은 은행에 쌓인다.
  능력치는 육성 턴이 건드리지 않는다 — 유저가 찍은 포인트만 오른다(§5).

  API 는 인터미션에서 유저 입력을 60초까지 기다린다. 응답이 없으면 기본값(전원
  훈련)으로 가고, 입력이 규칙을 어기면 거부 사유를 트레이스에 남기고 기본값으로
  간다 — 화면이 죽어도 스트림이 영원히 열려 있으면 안 된다.
