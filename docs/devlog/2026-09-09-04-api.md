- **회수 결정을 기록한다 — 굴에 두고 올 것인가**
  기획서 v3 §6.8. 끌려간 대원을 다시 데려올지 유저가 정하고, 그 결정이
  트레이스에 남는다. **회수 미션 개방은 넣지 않았다** — MVP 범위이고
  기획서 v3 §12 도 A단계를 "저장만" 으로 잡았다.

  미지불이 기본값이다. 화면이 답하지 않아도, 기한을 넘겨도 미지불이다 —
  "기한을 넘기면 자동 미지불" 이라는 규칙이 그대로 기본 동작이 된다.

  미지불한 사람은 record.forsaken 에 쌓인다. 「섭식」 학습 카드의 재료다(§8.4).
  회수를 만들기 전에는 이 목록을 만들 자리가 없었다 — 카드보다 회수를 먼저
  한 이유다.

  비용은 누적 투자 × 0.6 이다. 오래 키운 사람일수록 되찾는 값이 비싸고,
  그것이 딜레마의 축이다. 은화가 아직 없어 누적 투자를 성장 포인트로 센다 —
  은화가 들어오면 invested_of 의 몸통만 바뀐다.

  출동 슬롯 소모는 B단계다. A단계가 두 판뿐이라 "슬롯 하나를 회수 출동으로
  대체" 가 성립하지 않는다.

  API 는 POST /runs/{id}/recovery {"pay": [...]} 다.

  검증: ruff, pytest 420, 시드 교차 결정론, 프론트 22 + tsc.
