「돌파」를 관통 같은 다른 메커니즘으로 바꾸는 것은 밸런스 설계 변경이라 기획서 승인이 필요하다.

### T — 전령관 1턴 지연이 주석에만 있었다

라우터 주석은 *"그 지연은 core 가 판단한다"* 고 말했지만 core 에 그 코드가 없었다.
기획서 v3 §8.2 의 **병과 가치가 통째로 비어 있었다.**

- `Equipment.is_horn` — 어느 물건이 나팔인지는 **콘텐츠가** 안다. 도메인은 플래그만 본다.
- `runner.herald_present(battle)` — 나팔을 든 사람이 **서 있는가**. 쓰러지면 늦는다.
- 신호가 늦으면 `horn` 이벤트는 **닿은 턴에 하나만** 나가고 `delayed_from` 이 원래 턴을 말한다.
  지연을 따로 이벤트로 내면 리플레이가 그 턴에도 뿔피리를 분다(P0-D 회귀).
- 편성 화면이 **출정 전에** 경고한다 — 전투 중에 알면 늦다.

### V — 학습 카드에 출처 라운드가 없었다

기획서 v3 §11 은 카드마다 **출처 라운드·인물·종** 셋을 링크하라고 한다. 종과 인물은 있었고
라운드가 없었다 — 없으면 "판을 넘는 학습" 이 아니라 그냥 표시다.

`ActionRecord.mission` 과 `Battle.mission_no` 를 더해 기록이 회차를 지고 다닌다.
`record.forsaken` 도 `(id, 병과, 회차)` 3튜플이 됐다. 카드 패널이 「출처: 놀의 탈주 추적 · 7회차」로,
「섭식」은 *"7회차에 당신이 굴에 두고 온 오드에게서 배웠다"* 로 말한다.

검증: `ruff` · `pytest 458` · 프론트 22 · `tsc`.

## 수정 — 7차 (P1 Q · S)

### Q — 뿔피리 상한 분기를 어떤 테스트도 지나지 않았다

거절 판단이 라우터 함수 안에 있어 HTTP 로는 닿을 수 없었다 — **불면 그 판이 끝나므로
한 판에 한 번밖에 못 분다.** A단계의 2출동 계약으로는 3번째 충전에 구조적으로 도달 못 한다.

판단을 `RunSession.horn_refusal() -> str | None` 로 내렸다. 라우터는 그 문장을 409 에 실을 뿐이다
(`adapter/inbound/api` 는 얇다 — 백엔드 CLAUDE.md §11). **네 사유를 전부 지나는 테스트**가 붙었다:
전투 중 아님 · 이미 울림 · 다 씀 · 이미 끝난 판.

### S — E2 가 아무것도 재지 못했다

V4(“eval 이 v3 새 필드를 하나도 안 읽는다”)는 P0-E 에서 해결됐다(`grade_share`·`avg_taken` 등).
남은 V5 를 재 보니 **지표 탓이 아니었다.**

| 60시드 실측 | ON | OFF |
|---|---|---|
| 완주율 (균등) | 38% | 38% |
| 생환율 (균등) | 90% | 90% |
| 적 피해 총량 | 778.9 | 779.3 |
| 피해 집중도 | 0.656 | 0.660 |
| 적응 발동 | 1.2~2.2회/판 (무효 13~15%) | 0 |
| **적응이 지목한 대상을 보스가 실제로 때린 비율** | **14~34%** | — |

**진단**: 적응은 발동하고 `boss_focus` 도 실제로 바뀐다(무효는 13~15%뿐). 그런데 **행동에 못 닿는다** —
근접 보스는 전열이 살아 있는 한 후열에 못 닿는데(`resolve.py` 의 reachable) 지목 대상은 대개
후열의 반복 공격자·치유자다. 그래서 상태만 바뀌고 타격은 그대로다.

**고친 것**: E2 가 **승패 말고 메커니즘을 잰다.** `adapt_no_change_rate`(상태를 못 바꾼 비율)와
`focus_follow_rate`(지목을 실제로 때린 비율)를 집계에 넣고 CLI·차트가 보여준다. 둘 다
트레이스 후처리만으로 나온다(기획서 §3.1). 이제 차트가 "적응은 무의미하다" 가 아니라
**"적응은 일어나지만 지목의 66~86% 가 손에 닿지 않는다"** 고 말한다.

**보류(사유)**: 닿게 만드는 것 — 「돌파」가 후열까지 뚫게 하거나, 지목을 **닿는 대상 중에서만**
고르게 하는 것 — 은 밸런스 설계 변경이라 기획서 결정이 필요하다. 지금은 **측정된 사실**을
숨기지 않고 차트에 올린다.

검증: `ruff` · `pytest 459` · 프론트 22 · `tsc`. `eval/out/{e1,e2,e3}.json` 재생성.

| **2판** · 전령관 있음 | **0** | 28 |
| 2판 · 전령관 없음 | **0** | 29 |

`[win, retreat]` 이 `[retreat, win]` 으로 뒤집히고, 전령관이 없으면 왕복마다 1턴씩 밀린다.
**1차의 P0-D 는 검사한 한 경로만 고쳤다.** `replay_horn` 을 지나는 테스트가 저장소에 0개였다.

**고친 것**: `HornFn` 이 `(회차, 턴)` 을 받는다. 리플레이는 `delayed_from or turn` 으로 **원래 분 턴**을
복원하고 회차까지 맞춘다. 회귀 테스트는 **네 조합 전부**를 지난다(`test_뿔피리가_낀_판도_리플레이가_같은_판을_낸다`).
돌연변이 검증: 회차를 빼면 2건, `delayed_from` 을 빼면 3건이 빨개진다.

### R2. 판 시작 창에서 부른 뿔피리가 충전만 닳고 증발한다

`gate(True)` 가 `make_plan`(모델 호출) **앞에서** 열리는데 `horn_signal` 이 `turn <= 1` 을 "묵은 신호" 로
버렸다. 200 · `horn_left` 감소 · `horn` 이벤트 없음 · 판은 계속. 트레이스에 흔적이 0 이다.

**고친 것**: 묵은 신호는 **판 경계**에서 버린다(`RunSession.close_battle()`). 게이트가 그 자리를 정확히
안다 — `turn <= 1` 은 게이트가 생긴 뒤로 중복이었고, 중복인 채로 정상 입력을 먹었다.

### R3. 전령관이 없을 때 연타하면 영영 안 울린다

```python
if 울렸나 and not herald_present(battle): 늦은_신호 = battle.turn   # ← 대기 중이던 신호를 덮는다
elif 늦은_신호: 울렸나 = True                                        # ← 새 입력이 있으면 실행 안 됨
```
"안 울렸네" 하고 다시 누르는 것이 **정확히 최악의 수**였다 — 3턴+4턴+5턴에 누르면 6턴에 닿고 충전 3을 다 쓴다.

**고친 것**: 대기 중인 신호가 **먼저**다. 새 입력은 흡수된다. 그리고 신호가 닿기 전에 판이 끝나면
`horn` 을 `delivered: false` 로 남긴다 — 전에는 흔적 없이 사라져 유저가 "전원 살려 나왔다" 고 믿었다(실측 77회 중 3회).

## R21 — E1 이 무엇을 재고 있었나 (팀 결정 #14)

재검이 A/B 로 원인을 고정했다. 보스 없는 판에서 Fake 단장의 `focus = 가장 약한 적` 이
**후열 고블린 투석수**를 잡고, 근접은 전열이 살아 있는 한 후열에 못 닿아 타격이 되돌려졌다.
게다가 `_act` 가 지목을 **광역보다 먼저** 골라 광역 기술이 단일 대상으로 바뀌었다.
감독 OFF 는 지목이 없어 **우연히** 광역을 골랐다 — 그래서 E1 이 "감독은 해롭다" 고 말했다.

30시드 미션 7 실측:

| | 감독 ON (전) | 감독 OFF | 감독 ON (후) |
|---|--:|--:|--:|
| 파티가 준 피해 | 6,106 | 11,638 | **11,353** |
| 타격 수 | 563 | 1,287 | **1,307** |

**고친 것**(팀 결정 #14): 지목은 **닿는 적** 안에서만. 적 3기 이상이면 **광역이 지목보다 우선**
(단원 컨텍스트에는 적 목록이 없어 `available` 의 ATTACK 대상 수로 센다).

**다시 잰 E1** — 시드 200, Fake:

| 조합 | 완주 ON/OFF | 생환 ON/OFF | 완주 짝비교 | 생환 짝비교 |
|---|---|---|---|---|
| 중장병 몰빵 | 34% / 44% | 57% / 55% | ON만 17 · OFF만 39 · p=0.0046 | 43 · 38 · p=0.6570 |
| 균등 | **74% / 8%** | **90% / 45%** | ON만 134 · OFF만 1 · **p=0.0000** | 101 · 10 · **p=0.0000** |
| 방패병 몰빵 | 0% / 0% | 36% / 28% | 0 · 0 · p=1.0000 | 46 · 31 · p=0.1100 |
| **전령관 없음** | **21% / 0%** | **66% / 42%** | ON만 42 · OFF만 0 · **p=0.0000** | 75 · 27 · **p=0.0000** |

**기획서 §8.1 이 이제 지지된다** — 「전령관 없음」이라는 **나쁜 조합**에서 감독이 두 축 모두
유의하게 좋다. 「중장병 몰빵」의 완주율은 여전히 ON 이 낮지만(p=0.0046) 폭이 42p → 10p 로 줄었고
생환은 잡음이다. **이 잔여는 튜닝으로 지우지 않고 측정된 사실로 남긴다.**

E2 도 다시 쟀다 — 지목 명중이 23% → **47%** 로 바로잡혔고(R12), 적응 ON/OFF 는 여전히
승패에서 구별되지 않는다. 그 사실을 `adapt_no_change_rate`·`focus_follow_rate` 가 말한다.
